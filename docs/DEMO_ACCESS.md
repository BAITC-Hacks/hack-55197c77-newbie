# Демонстрационный доступ для экспертов

Пункт 5.6.6 предоставленного Положения требует проверки ключевой функциональности
без личных аккаунтов, персональных подписок и закрытых учётных записей участников.
Текущая локальная интеграция OpenAI работает, но внешнее демо ещё не опубликовано.

## Рекомендуемый вариант: сайт без входа

Эксперт открывает HTTPS-ссылку, выбирает меры, рассчитывает сценарий и получает
новый AI-ответ. Учётные данные участника ему не передаются.

До указания готовности этого способа необходимо:

1. Выбрать хостинг Python с HTTPS и серверным хранением секретов. Основной код
   продолжает разрабатываться только в репозитории Организатора.
2. Подготовить сервер для размещения: production-сервер, настройка внешнего адреса
   и origin-проверки за HTTPS-прокси, ограничение частоты AI-запросов и расходов.
   Текущий `web_server.py` слушает только `127.0.0.1` и рассчитан на локальную проверку.
3. Разместить версию из рабочего репозитория. В настройках сервиса хранить
   отдельный демонстрационный API-ключ, адрес и модель; в Git секрет не добавлять.
4. Из другого браузера без авторизации проверить весь путь: пример → Score 56,54
   → настоящий AI-ответ; затем изменить район и проверить новый сценарий.
5. Обеспечить доступность на период проверки 24–28 сентября и, при выходе в финал,
   Demo Day 29 сентября. При этом оцениваться должна зафиксированная версия
   соревновательной части, без функциональных доработок после 18:00 23 сентября.
6. До дедлайна добавить фактическую ссылку, инструкцию и срок доступности в README
   и материалы сдачи. Не указывать несуществующий или непроверенный адрес.

Хостинг ещё не выбран и не оплачен, публичная ссылка отсутствует. Эти действия
не отмечены выполненными. Одна только публикация статических HTML/CSS не обеспечит
работу Python API и не позволит безопасно хранить AI-ключ.

## Альтернатива: отдельный проверочный ключ

Этот вариант подходит, если Организатор предусмотрел закрытый канал передачи
демонстрационных доступов. Команда передаёт отдельный ключ и параметры, эксперт
запускает код по README и помещает ключ в локальный `.env`. Создавать собственный
платный аккаунт OpenAI эксперту не требуется.

Перед передачей нужно уточнить у Организатора допустимый канал и проверить
реальный запрос с этим доступом. Ключ не размещается в README, публичных issues,
коммитах, презентации или переписке, доступной посторонним. Пароль личного аккаунта
участника не передаётся. Команда отвечает за доступный лимит на период проверки.

## Что не подменяет демонстрационный доступ

Локальный адрес `127.0.0.1` на компьютере участника не открывается у эксперта.
Тестовые ответы из `tests/`, текст по правилам, скриншот и запись успешного запроса
показывают часть результата, но не обеспечивают отправку нового сценария в LLM.
Их нельзя представлять как уже предоставленный работающий AI-доступ.
