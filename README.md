# Аким на 5 часов — Newbie

Симулятор распределения городского бюджета для HackAlem AI.
Пользователь выбирает пять мероприятий, а модель рассчитывает изменения
показателей районов и Astana Quality of Life Score.

## Текущее состояние

Реализованы исходный датасет, валидатор решений, воспроизводимый расчёт Score
и локальный веб-интерфейс с интерактивной картой районов и письменным заключением.
Добавлен модуль реального LLM-анализа через API: модель объясняет готовый расчёт,
сочетание решений, риски и возможные реакции жителей. Для его работы нужно
настроить доступ к AI-сервису. Без доступа работает явно обозначенный разбор по правилам.
Интеграция проверена автоматическими тестами с подменой ответа провайдера
и настоящим запросом к OpenAI API с моделью `gpt-6-luna` 23 сентября 2026 года.
На примере организаторов получены пояснения всех пяти мер и пяти направлений,
сильные стороны, риски и рекомендации. Контрольный Score остался **56,54307**.
Рабочий ключ хранится только локально; для запуска в другом окружении нужен свой доступ.

## Интерактивная карта

В корне проекта запустите:

```powershell
python -X utf8 web_server.py
```

Откройте **http://127.0.0.1:8000** в браузере. Окно терминала оставьте открытым;
`Ctrl+C` останавливает сервер. Если порт занят, используйте
`python -X utf8 web_server.py --port 8001` и откройте соответствующий адрес.
В PyCharm можно запустить `web_server.py` или выполнить команду во встроенном Terminal.

1. Нажмите на район на карте или на кнопку с его названием под картой.
2. Справа появятся оценка района, доля населения и десять шкал по пяти направлениям.
3. Показатели ниже 40 отмечены как критические; пунктир на шкале обозначает порог 40.
4. Нажмите «Загрузить пример», затем «Рассчитать сценарий».
5. Балл города должен стать **56,54**, остаток бюджета — **5**, критических значений — **0**.
6. Выберите Нуру: школы изменятся с 38 до 48, поликлиники — с 35 до 43,75.
7. Переключайте «До / После», чтобы сравнивать результаты.
8. Под результатом расчёта нажмите «Читать заключение о последствиях»:
   отображаются общий вывод, изменения пяти направлений, нерешённые проблемы
   и объяснение каждого из пяти выбранных мероприятий.

### Письменное заключение

Заключение воспроизводимо и работает без сети и ключей. Оно формируется модулем
`conclusions.py` из готового расчёта и авторских пояснений всех 14 мероприятий.
Это **генерация по правилам, не LLM**. Для AI-анализа нажмите отдельную кнопку
после подключения модели, как описано ниже.

- Числа берутся из модели: бюджет, Score, дельты, задержки, критические показатели и синергии.
- Реакции жителей обозначены как возможные гипотезы, а не опрос или проценты довольных.
- Неизменившиеся направления не объявляются ухудшившимися из-за отсутствия расходов.
- Побочные эффекты между направлениями учитываются: например, M3 улучшает E2
  даже при нулевых прямых расходах на экологию. Объёмы CO₂ не вычисляются.
- Для M1 возможны возражения автомобилистов, но текст не утверждает рост пробок:
  T1 в датасете растёт. Для M11, напротив, снижение T1 — явный компромисс модели.
- Эффекты отдельных мер показываются после учёта задержки, до ограничения 0–100;
  синергии выделены отдельно. Средние показателей по направлениям взвешены по населению.
- Порог 50 в списке остаточных проблем — пояснительный ориентир, а не новый штраф.
- При редактировании сценария старое заключение скрывается до нового расчёта.

Можно составить собственный набор из 14 мероприятий и выбрать районы их реализации.
Расчёт запрещён при превышении бюджета и неполном наборе. Остальные ограничения
проверяет сервер: он возвращает причины, если сценарий невалиден. При изменении выбора
предыдущий результат сбрасывается, чтобы не показывать устаревшие показатели.
Выбор хранится в памяти страницы; обновление страницы его сбрасывает.

Карта — **авторская SVG-схема**, а не точные географические границы Астаны.
Внешние карты, интернет и API-ключи для карты и численного расчёта не нужны.
Цвет района соответствует оценке D: ниже 50, от 50 до 60, от 60.
Это отдельная визуальная шкала; официальный критический порог 40 применяется
к каждому из десяти показателей. HTML/CSS/JavaScript отображают интерфейс,
все итоговые расчёты выполняет Python. Сервер доступен только на этом компьютере.

## Установка и запуск

Нужен Python 3.10 или новее. Сторонние библиотеки не требуются.
Карта, расчёт и заключение по правилам работают без сети. Для AI-анализа нужен
интернет и API-ключ. Все команды выполнять в корне репозитория.

```powershell
python --version
python main.py
python main.py examples/organizer.json
python -m unittest discover -s tests -v
```

Для Linux/macOS используйте `python3`, если `python` отсутствует.
Вывод — JSON с показателями, оценками районов, расходами и итоговым `score`.
Некорректный сценарий возвращает `valid: false`, `score: null`, причины
в `errors` и код завершения 2. Он не получает фиктивный числовой балл.

### Контрольный пример

Без действий: Score **52.55768**; среднее города **56.8624**;
минимальная оценка района **49.18**; критических показателей **2**.

`examples/organizer.json`: M7, M8, M10 в Нуре, M12 по городу,
M5 в Сарыарке. Стоимость **95**, остаток **5**, Score **56.54307**,
критических показателей **0**. Это соответствует примеру организаторов.

Чтобы проверить другой сценарий, скопируйте JSON-пример, замените меры/районы
и передайте путь к новому файлу в `python main.py путь/сценарий.json`.
Для городской меры поле `district` не требуется; `null` также означает отсутствие района.

## Подключение AI

1. Получите у организаторов или выбранного провайдера ключ API, идентификатор
   модели и базовый адрес API. Ключ, модель и адрес должны относиться к одному сервису.
2. Создайте локальный `.env` из шаблона (существующий файл не перезаписывается):

   ```powershell
   if (!(Test-Path .env)) { Copy-Item .env.example .env }
   notepad .env
   ```

3. Впишите `AI_API_KEY`. В шаблоне выбрана `AI_MODEL=gpt-6-luna` —
   [экономичная модель OpenAI с поддержкой structured outputs](https://developers.openai.com/api/docs/models/gpt-6-luna).
   Доступность в вашем API-проекте проверяется реальным запросом; при необходимости
   укажите другую доступную совместимую модель. Для OpenAI оставьте
   `AI_BASE_URL=https://api.openai.com/v1`; для другого совместимого сервиса
   укажите его документированный HTTPS-адрес. Модель должна поддерживать
   Chat Completions и `max_completion_tokens`. По умолчанию используется
   `AI_OUTPUT_FORMAT=json_schema`; если сервис поддерживает только JSON mode,
   задайте `json_object`. Это адаптер совместимого API, не поддержка любых моделей.
4. Сохраните файл. Настройки перечитываются при запросе, перезапуск не требуется.
   Не публикуйте ключ в GitHub, чатах или README: `.env` исключён из Git.
   Переменные окружения с теми же именами имеют приоритет над `.env`.
5. В интерфейсе загрузите пример, рассчитайте сценарий и нажмите
   **«Получить AI-анализ»**. Дождитесь надписи **«Ответ AI получен»** с моделью и временем.
   Наличие настроек само по себе не подтверждает доступ к API.

После успешного запроса появятся общий AI-вывод, сильные стороны, риски и
рекомендации для дальнейшего сравнения. Пояснения всех пяти направлений и
последствия каждой выбранной меры обновятся ответом модели. Числа, бюджет и Score
останутся результатом Python. AI не ищет оптимум и не меняет решения пользователя.
Рекомендации и реакции жителей — качественные гипотезы, не доказанный прогноз.

Запрос выполняется только по кнопке и может расходовать оплачиваемый лимит API.
Сервис получает синтетический датасет, выбранные меры/районы, исходный и итоговый
расчёт и авторские пояснения. Ключ используется только сервером для авторизации;
в браузер и в содержание промпта он не передаётся. История запросов не сохраняется
приложением; обработка данных самим провайдером зависит от его условий.

Ошибки ключа, лимита, сети, отказ или неполный ответ показываются отдельно.
Автоматических повторов нет. Повторная попытка — по кнопке; одновременно выполняется
не более одного AI-запроса. При смене решений ответ старого сценария скрывается.
Сервис ожидается до 60 секунд на сетевую операцию; очень медленный ответ может занять дольше.
Ответ ограничен по размеру, проверяется наличие ровно пяти выбранных мер и всех
пяти направлений. Проверка структуры не гарантирует фактическую точность текста модели.

Для проверки без расходов на API запустите общий набор тестов: ответы провайдера
в тестах заменены явно обозначенными фикстурами. В рабочем приложении тестовых
AI-ответов нет. Настоящий запрос на примере организаторов и качество его текста
проверены 23 сентября 2026 года: ответ охватил все выбранные меры, реакции жителей
были обозначены как возможные, отсутствие вложений не объявлялось ухудшением.
Сброс устаревшего разбора при смене сценария проверен отдельно с тестовым ответом.
После изменения ключа, модели или окружения повторите проверку реального запроса.

Протокол: [Structured Outputs в OpenAI API](https://developers.openai.com/api/docs/guides/structured-outputs).

## Правила и формула

- Бюджет 100, ровно пять уникальных мероприятий, не более двух из одного направления.
- Район обязателен для районной меры. Городская мера действует на все районы.
- Учитываются все три несовместимости и три синергии из датасета.
- Эффект меры умножается на `(8 - lag) / 8`; бонус синергии не масштабируется.
- Показатели ограничиваются диапазоном 0–100 после сложения всех эффектов.
- Оценка района — сумма показателей с заданными весами.
- `Score = 0.7 * population_weighted_average + 0.3 * minimum_district_score - critical_count`.
- Критическим считается значение **строго меньше 40**. Округление внутри расчёта не применяется.

**Принятая трактовка:** используются подробные правила датасета: пять мер
могут охватывать не все пять направлений. Это соответствует контрольному примеру.
В общем ТЗ формулировка про пять направлений отличается; трактовку необходимо
подтвердить у организаторов.

## Архитектура

- `data/city.json` — неизменяемые исходные условия, веса, каталог мер и правила.
- `simulator.py` — проверка сценария и детерминированная математика.
- `conclusions.py` — письменный разбор рассчитанного сценария.
- `ai_analysis.py` — настройки, промпт, вызов LLM и проверка структуры AI-ответа.
- `.env.example` — шаблон настроек без секретов; `.env` остаётся локальным.
- `data/measure_explanations.json` — логика 14 мер и гипотезы реакции жителей.
- `main.py` — консольный интерфейс и чтение JSON.
- `web_server.py` — локальный HTTP-сервер и API расчёта на стандартной библиотеке Python.
- `web/` — интерактивная SVG-карта, карточки районов, выбор мер и шкалы до/после.
- `examples/organizer.json` — проверочный сценарий.
- `tests/test_simulator.py` — контрольные расчёты и проверки ограничений.
- `tests/test_web.py` — проверка HTTP-запуска, расчёта и обработки ошибочных запросов.
- `tests/test_conclusions.py` — фактическая согласованность заключений с расчётом и покрытие всех мер.
- `tests/test_ai_analysis.py` — контракт LLM, ошибки сервиса, конфигурация и отсутствие утечек ключа.

LLM-модуль объясняет готовые расчёты и компромиссы; он не является
источником чисел или заменой валидатора. Вклад отдельных мер выводится
как изменение показателей до ограничения диапазона, а не как аддитивный вклад
в нелинейную итоговую формулу Score.
