# Аким на 5 часов — Newbie

Симулятор распределения городского бюджета для HackAlem AI.
Пользователь выбирает пять мероприятий, а модель рассчитывает изменения
показателей районов и Astana Quality of Life Score.

## Текущее состояние

Реализованы исходный датасет, валидатор решений, воспроизводимый расчёт Score
и локальный веб-интерфейс с интерактивной картой районов.
**LLM-анализ пока не реализован**: это промежуточная версия симулятора.

## Интерактивная карта

В корне проекта запустите:

```powershell
python -X utf8 web_server.py
```

Откройте **http://127.0.0.1:8000** в браузере. Окно терминала оставьте открытым;
`Ctrl+C` останавливает сервер. Если порт занят, используйте
`python -X utf8 web_server.py --port 8001` и откройте соответствующий адрес.
В PyCharm можно запустить `web_server.py` или выполнить команду во встроенном Terminal.

1. Нажмите на район на карте или на кнопку с его названием под картой.
2. Справа появятся оценка района, доля населения и десять шкал по пяти направлениям.
3. Показатели ниже 40 отмечены как критические; пунктир на шкале обозначает порог 40.
4. Нажмите «Загрузить пример», затем «Рассчитать сценарий».
5. Балл города должен стать **56,54**, остаток бюджета — **5**, критических значений — **0**.
6. Выберите Нуру: школы изменятся с 38 до 48, поликлиники — с 35 до 43,75.
7. Переключайте «До / После», чтобы сравнивать результаты.

Можно составить собственный набор из 14 мероприятий и выбрать районы их реализации.
Расчёт запрещён при превышении бюджета и неполном наборе. Остальные ограничения
проверяет сервер: он возвращает причины, если сценарий невалиден. При изменении выбора
предыдущий результат сбрасывается, чтобы не показывать устаревшие показатели.
Выбор хранится в памяти страницы; обновление страницы его сбрасывает.

Карта — **авторская SVG-схема**, а не точные географические границы Астаны.
Внешние карты, интернет и API-ключи для этого интерфейса не нужны.
Цвет района соответствует оценке D: ниже 50, от 50 до 60, от 60.
Это отдельная визуальная шкала; официальный критический порог 40 применяется
к каждому из десяти показателей. HTML/CSS/JavaScript отображают интерфейс,
все итоговые расчёты выполняет Python. Сервер доступен только на этом компьютере.

## Установка и запуск

Нужен Python 3.10 или новее. На этом этапе сторонние библиотеки, API-ключи
и внешние сервисы не требуются. Все команды выполнять в корне репозитория.

```powershell
python --version
python main.py
python main.py examples/organizer.json
python -m unittest discover -s tests -v
```

Для Linux/macOS используйте `python3`, если `python` отсутствует.
Вывод — JSON с показателями, оценками районов, расходами и итоговым `score`.
Некорректный сценарий возвращает `valid: false`, `score: null`, причины
в `errors` и код завершения 2. Он не получает фиктивный числовой балл.

### Контрольный пример

Без действий: Score **52.55768**; среднее города **56.8624**;
минимальная оценка района **49.18**; критических показателей **2**.

`examples/organizer.json`: M7, M8, M10 в Нуре, M12 по городу,
M5 в Сарыарке. Стоимость **95**, остаток **5**, Score **56.54307**,
критических показателей **0**. Это соответствует примеру организаторов.

Чтобы проверить другой сценарий, скопируйте JSON-пример, замените меры/районы
и передайте путь к новому файлу в `python main.py путь/сценарий.json`.
Для городской меры поле `district` не требуется; `null` также означает отсутствие района.

## Правила и формула

- Бюджет 100, ровно пять уникальных мероприятий, не более двух из одного направления.
- Район обязателен для районной меры. Городская мера действует на все районы.
- Учитываются все три несовместимости и три синергии из датасета.
- Эффект меры умножается на `(8 - lag) / 8`; бонус синергии не масштабируется.
- Показатели ограничиваются диапазоном 0–100 после сложения всех эффектов.
- Оценка района — сумма показателей с заданными весами.
- `Score = 0.7 * population_weighted_average + 0.3 * minimum_district_score - critical_count`.
- Критическим считается значение **строго меньше 40**. Округление внутри расчёта не применяется.

**Принятая трактовка:** используются подробные правила датасета: пять мер
могут охватывать не все пять направлений. Это соответствует контрольному примеру.
В общем ТЗ формулировка про пять направлений отличается; трактовку необходимо
подтвердить у организаторов.

## Архитектура

- `data/city.json` — неизменяемые исходные условия, веса, каталог мер и правила.
- `simulator.py` — проверка сценария и детерминированная математика.
- `main.py` — консольный интерфейс и чтение JSON.
- `web_server.py` — локальный HTTP-сервер и API расчёта на стандартной библиотеке Python.
- `web/` — интерактивная SVG-карта, карточки районов, выбор мер и шкалы до/после.
- `examples/organizer.json` — проверочный сценарий.
- `tests/test_simulator.py` — контрольные расчёты и проверки ограничений.
- `tests/test_web.py` — проверка HTTP-запуска, расчёта и обработки ошибочных запросов.

Будущий LLM-модуль будет объяснять готовые расчёты и компромиссы; он не будет
источником чисел или заменой валидатора. Вклад отдельных мер сейчас выводится
как изменение показателей до ограничения диапазона, а не как аддитивный вклад
в нелинейную итоговую формулу Score.
